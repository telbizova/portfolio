# Портфолио — правила проекта

Персональный сайт-портфолио UX/UI-дизайнера. Один автор, без бэкенда, без CMS.
Язык контента — русский. Всё, что ниже, обязательно к соблюдению.

---

## Стек

- **Astro** (статика, без SSR)
- **Tailwind CSS v4** — только через токены, см. ниже
- **Markdown/MDX** для кейсов — один файл на кейс в `src/content/cases/`
- Деплой: GitHub → Vercel

**Никаких новых зависимостей без явного разрешения.** Если кажется, что нужна
библиотека — сначала спроси и объясни, почему без неё нельзя. Анимации, слайдеры,
иконки, утилиты для дат — всё это почти всегда решается 15 строками своего кода.

Не подключать: UI-киты (shadcn, MUI, Chakra), CSS-in-JS, аналитику, шрифтовые
CDN кроме локально положенных woff2.

## Структура сайта

```
/                     главная
/cases/[slug]         страница кейса
```

### Главная

Одна колонка по центру шириной `--container`, без шапки и навигации.

1. **Первый экран** — круглый портрет (`--avatar`), приветствие с ролью
   (заголовок), пара слов о себе серым, кнопки-пилюли «CV ↗» и «Telegram ↗».
2. **Проекты** — сгруппированы по компаниям (`src/data/companies.ts`): над
   группой строка с иконкой, названием компании и периодом. Карточки белые
   (`--surface`, `--radius`), все на всю колонку, 700×440. В карточке: категории
   через ромбики, название, описание продукта, скриншот, обрезанный правым и
   нижним краем; поверх скриншота могут лежать виджеты. Карточка кликабельна целиком.
3. **Плашка при скролле** — когда кнопки первого экрана уходят из вида, внизу
   по центру появляется та же пара кнопок на полупрозрачной подложке с блюром.

Секций «Опыт», «Рекомендации», «Контакты» и страницы «Обо мне» в макете нет —
не добавлять без макета.

### Страница кейса

Верстать по фреймам «Страница проекта» и «Страница проекта - скролл».

**Контент** — в `src/content/cases/<slug>.md`. В полях файла: `hero` / `heroAlt`
(первая картинка), `about` (роль, таймфрейм, команда), `note` (плашка, например
про NDA). Текст — обычный Markdown, его вёрстку задаёт `.case-prose` в
`global.css`. Если у кейса нет `about`, показывается заглушка из макета
(`CasePlaceholder.astro`). Меню разделов справа строится само: «О проекте» +
все заголовки `##`.

**Как писать Markdown кейса:**
- `## Раздел` — заголовок раздела, попадает в меню справа.
- `### 1. Подраздел` — нумерованный подраздел внутри раздела.
- Абзац из одной жирной строки `**Один проект**` — заголовок блока, следующий
  абзац встаёт под ним на 4px. Такие абзацы помечает плагин
  `src/lib/case-block-titles.mjs` (движок Markdown Sätteri, встроен в Astro);
  абзац, который только начинается с жирного, остаётся обычным текстом.
- Список `- **Название**` + со следующей строки описание — пункт с ромбиком.
- `1. …` — нумерованный список (как в «Процессе»).
- Картинка — `<figure class="case-figure">` с `<figcaption>`; пока скриншотов
  нет — пустая рамка `<div class="case-figure__frame" role="img" aria-label="…">`.

**Правила вёрстки из макета** (десктоп; на телефоне отличается только отмеченное):
- Колонка 700px, текст с отступом 80px по бокам, картинки на всю ширину колонки.
- Шапка кейса: название 32/40 (на телефоне 28/36), описание 17/27 на 60%.
- Картинка: белая карточка 700×393, скругление 28 (на телефоне 20), скриншот
  533×300 по центру, скругление 10, обводка 4px `--fg` на 12%. Подпись 14/22
  Medium на 40%, отступ 20 от картинки.
- «О проекте»: подписи 13/14 Semi Bold капсом на 40%, значения 17/27; роль и
  таймфрейм в две колонки через 24, до команды 28. Плашка NDA 607px, подложка
  `--note` на 8%, скругление 12, отступы 24/32 (на телефоне 16/20).
- Заголовок раздела 24/1 Regular −3%; подраздел «1. …» 20/28 Regular −2%;
  жирная строка-заголовок 17/27 Medium; текст 17/27 −2%.
- Отступы: между разделами 68; заголовок → текст 24 (всегда, в том числе перед
  списком и подразделом); подраздел → текст 20; между абзацами 17 (на телефоне 12);
  абзац → жирная строка-заголовок 20; жирная строка → её текст 4; до и после
  картинки 32, две картинки подряд 20; вступление → список 24; после списка 24;
  между пунктами списка 16.

## Дизайн-токены

Всё в `src/styles/tokens.css` как CSS custom properties и в `@theme` в
`src/styles/global.css` (стандартные цвета, шрифты, размеры текста и
скругления Tailwind отключены). **Хардкод цвета, размера шрифта или отступа в
компоненте = ошибка.** Значения берутся из макета через Inspect в Figma, а не
на глаз. Если нужного токена нет — возьми значение из макета или спроси.

- **Цвет:** `--bg` #F0F0F0, `--surface` #FFF, `--fg` #1E1E1E (оттенки текста —
  `text-fg/30`…`/80`, как прозрачность в макете), `--accent` #3A3A3A (кнопки),
  `--line` #CECECE, `--glass` #979797 (плашка, на 20%), `--bar-stroke` #E2E2E2
  (обводка плашек, на 70%), `--company` / `--company-icon` (компания над
  проектами), `--muted` #484848 (даты, на 60%), `--wave` (подчёркивание в футере).
- **Шрифт:** Inter, локально в `public/fonts/` (woff2, кириллица,
  `font-display: swap`). Роли — классы `text-<роль>` с размером, интерлиньяжем и
  трекингом из макета (`--type-*`): главная — `hero`, `lead`, `meta`, `title`,
  `body`, `tag`; кнопки — `button`, `button-sm`, `nav`, `footer`; кейс —
  `case-title`, `section`, `subsection`, `prose`, `label`, `caption`.
  Имя роли не должно совпадать с именем цвета: `text-X` применит только одно.
- **Отступы:** числовая шкала Tailwind с шагом 4px (`--space`), дробные шаги
  дают значения из макета: `1.5` = 6px, `12.5` = 50px, `17.5` = 70px.
  Между абзацами — `mt-paragraph` (17px).
- **Размеры:** `--container` 700px, `--lead-width` 520px, `--card-text` 443px,
  `--avatar` 120px.
- **Скругления:** `--radius` 28px (карточки), `--radius-image` 10px
  (скриншоты), `--radius-bar` 16px (плашка на главной), `--radius-button` 12px
  (кнопки первого экрана), `--radius-square` 8px (мелкие кнопки, «Наверх»,
  «Следующий кейс»), `--radius-pill` (портрет).

## Чего не делать

Дефолты, по которым сайт мгновенно читается как сгенерированный:

- Градиенты в фонах и заголовках, особенно фиолетово-синие
- Glassmorphism и `backdrop-blur` — кроме плашки с кнопками при скролле из макета
- Тени под всем подряд. Тень — только если элемент реально над плоскостью
- Скругления вне токенов
- Emoji в интерфейсе и в заголовках секций
- Тексты-заглушки вида «Transforming ideas into digital experiences»
- Иконки-плейсхолдеры вместо реальных скриншотов
- Заметные анимации появления (вылеты, масштаб, повороты). Допустимо только
  деликатное появление через `data-reveal` (прозрачность и сдвиг на
  `--reveal-shift`) и микроанимации на токенах `--dur-*` / `--ease-out`;
  исключение — карточки проектов на главной (`data-reveal="card"`): они
  поднимаются и дорастают заметнее, содержимое внутри не анимируется;
  всё отключается при `prefers-reduced-motion`

Если сомневаешься между «добавить эффект» и «не добавлять» — не добавляй.

## Вёрстка

- Семантические теги: `header`, `nav`, `main`, `section`, `article`, `footer`.
  Один `h1` на страницу, уровни заголовков не пропускать
- Все интерактивные элементы доступны с клавиатуры, видимый `:focus-visible`
- `alt` у каждой картинки — описательный, не «image»
- Контраст текста не ниже 4.5:1
- Адаптив от 360px. Проверять не только мобилу и десктоп, но и 600–900px
- Картинки: `<Image>` из Astro, всегда с `width`/`height`, формат webp
- Уважать `prefers-reduced-motion`

## Как работаем

1. **По одной секции за раз.** Не генерируй страницу целиком. Сделал блок —
   останавливаешься, я смотрю превью.
2. **Перед сложным блоком сначала план текстом**, потом код.
3. **После каждого принятого блока — коммит** с осмысленным сообщением на
   английском, в императиве: `add hero section`, `fix grid on tablet`.
   Не коммить всё одной пачкой.
4. **Если я кидаю скриншот с правкой** — чини именно то, что на нём, не
   переписывай соседние компоненты заодно.
5. **Не трогай токены без спроса.** Если блок не получается собрать из
   существующих — это повод обсудить, а не добавить новое значение молча.
6. **Не выдумывай контент.** Если текста для секции нет, оставь
   `TODO: текст` и скажи мне, что нужно написать.
